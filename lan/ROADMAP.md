# 网友接力路线图

欢迎从下面选择一项，在 Issue 中认领。当前是 A/B/C 原型，任务状态以实际合并和验证为准。原游戏 HTML 继续只读，新增实现全部放 `lan/`。

## 已完成的基础

- [x] A：零依赖 Node HTTP/WebSocket、房间、20连接容量、构建/种子/地图校验。
- [x] B：远程身体、紧凑名字牌、20Hz位姿、插值、枪火和空间枪声。
- [x] C：房主唯一 AI 和伤害、敌人生命周期、生命/弹药/换弹/击杀、晚加入、整轮重开。
- [x] 修复机械狗房主端死亡残留，以及房主刷新后画面继续但本机键鼠冻结。

## 优先接力：D 合作流程

建议拆成下面几个独立 PR。D1 先确定新的流程状态结构；后续 PR 基于它扩展，避免各客户端自行推进原单机控制器。

| 任务 | 建议修改位置 | 可验收的结果 |
|---|---|---|
| D1 共享流程状态 | `combat.js`、`combat-protocol.js`、`server.js` | 房主发布任务阶段与目标状态；两端 HUD 一致；晚加入拿到当前进度；旧 round 消息不能回退状态 |
| D2 共享中继/任务交互 | `net.js`、`combat.js` 与协议 | 任意玩家发交互意图，房主统一校验位置和状态；重复请求只生效一次；两端任务同步完成 |
| D3 波次与敌人生成 | 房主模拟与流程状态 | 只由房主生成下一批敌人；两端 enemyId/数量一致；不超过原对象池容量；重开不残留旧实体 |
| D4 个人复活与全灭 | 玩家权威状态、HUD与流程 | 个人复活不重置全队任务/敌人；全员阵亡统一结算；复活后键鼠、弹药和生命一致 |
| D5 共享撤离/结算 | 目标状态、交互与HUD | 条件满足后开放同一撤离目标；是否需要全员到达有明确规则；所有客户端进入相同结算 |

每项至少覆盖：双端正常路径、晚加入、重复/迟到意图、房主暂停、房主离线、整轮重开。当前政策是房主离开结束本轮、顺延房主明确重开；如果要改变该政策，请单独讨论和实现权威迁移。

## E 双队对抗

- [ ] 先讨论玩法：胜负目标、计分、友伤、出生保护和复活规则。
- [ ] 房主统一判定玩家命中和伤害，不把客户端枪火表现当伤害确认。
- [ ] 根据队伍安排出生点，减少出生重叠和立即被击杀。
- [ ] 双队 HUD、计分和整轮胜负；晚加入/离开不把旧队伍状态串到新 round。

现在的 `pvp` 仅分队和改变颜色，不具备玩家互伤或对抗胜负。

## F 稳定性与多设备

- [ ] 两台以上真实设备测试：有线/Wi-Fi、不同浏览器和不同画质，记录帧率、延迟和带宽。
- [ ] 20个真实浏览器性能测试；目前20连接协议测试不证明20人游戏流畅。
- [ ] 弱网与长时间运行：高延迟、抖动、重连、慢接收者、后台定时器节流。
- [ ] 输入回归：锁鼠/解锁、F2、暂停继续、刷新、个人死亡、重开；保持本机控制与战斗状态分离。
- [ ] 移动端触控与小屏大厅适配。
- [ ] 敌人/远程显示反复创建销毁后的内存、骨架和材质回收。
