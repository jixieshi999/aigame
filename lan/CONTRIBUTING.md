# 欢迎接力

这个项目已支持共享战斗、中继、波次、个人复活、全灭与撤离结算。接下来需要双队对抗与多设备性能验证；也欢迎修复同步问题、改善手感和提交真实设备测试结果。

## 开始前

先阅读 [README](README.md) 运行游戏，再看 [ROADMAP](ROADMAP.md) 选择任务。新建 Issue 说明你要接哪一块、预期行为和验证方式，避免多人重复修改同一模块；修复明确的小问题可以直接发 PR。

建议每个 PR 只解决一件事。描述里写清“什么操作会触发、现在怎样、改后怎样”，附运行命令和实际结果。未做的设备、性能或浏览器检查请明确注明。

## 必须保留的约定

- 原 `几猫国产3A大作_V1.html` 只读。不要重新格式化、改写、覆盖或生成完整副本；服务器只在 HTTP 响应内存中注入脚本。原构建的 SHA-256 在 README 和服务器常量中。
- 所有新增实现、详细文档和测试继续放在 `lan/`，根目录 README 仅作 GitHub 首页入口；保留 HTML 与 `lan/` 的相对位置。不要为了绕过构建校验直接改哈希。
- 正常运行只用 Node 内置模块，不给服务器引入 npm 依赖。Playwright 仅为可选开发测试工具。
- 只有房主发布敌人、生命、弹药和命中结果。客户端提交意图，显示端不得运行第二份敌人 AI 或重复结算伤害。
- 只传显式协议，不能全量转发游戏事件总线。新增消息要在服务器校验身份、字段、大小、频率和 roundId，并补充相应测试。
- 昵称用 textContent 或 Canvas 文本，不能写入 innerHTML。渲染资源按所有权释放，不能 dispose 原游戏共享的几何体或纹理。
- 更改战斗、暂停、死亡、刷新或重开时，同时验证“世界是否继续”和“本机键鼠是否正常”。不要再次用结束战斗状态停止整个本机控制循环。

## 目录导航

| 路径 | 应从这里入手的工作 |
|---|---|
| `lan/server.js` | HTTP/WS、房间、身份、协议分发与生命周期 |
| `lan/combat-protocol.js` | 战斗快照、事件及数值白名单 |
| `lan/net.js` | 大厅、地图摘要、远程玩家、名字牌、枪火 |
| `lan/combat.js` | 房主战斗模拟、伤害归属、敌人骨骼显示 |
| `lan/flow-shared.js`、`lan/flow-coop.js` | 出生/复活/结算的共用组件与房主合作流程 |
| `lan/test/` | Node 单元/协议测试和可选浏览器测试 |

## 验证

在仓库根目录运行：

```sh
node --test lan/test/server.test.js lan/test/client.test.js lan/test/combat.test.js lan/test/flow.test.js
```

已有48项测试（保留原32项）。涉及界面/输入/同步时，另用两个浏览器在同一房间实测。浏览器自动化的安装和命令见 README；输出会写入被忽略的 `lan/test/artifacts*/`。个人复活必须保留真实键鼠回归，不能调用 game.start 重置整局。

反馈问题时请提供浏览器版本、操作系统、同机还是多设备、两端操作顺序、房主身份和预期/实际结果。截图可附大厅状态；控制台只读 `__LAN.snapshot()` 能帮助定位，但上传前请去掉不必要的个人或网络信息。
